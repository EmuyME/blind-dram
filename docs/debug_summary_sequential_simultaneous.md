# 逐次モード・一斉モードデバッグ結果まとめ

## 実装確認

### ✅ 逐次モードの実装

1. **プレゼンターページ** (`app/session/[joinToken]/presenter/[sampleId]/page.tsx`)
   - `revealed`状態になった場合、逐次モードであれば結果ページに自動リダイレクト（280-284行目）
   - `revealed/closed`状態の表示で、逐次モードの場合は「結果を見る」ボタンを表示（1157-1175行目）

2. **参加者のセッションページ** (`app/session/[joinToken]/page.tsx`)
   - `revealed`状態のサンプルがある場合、結果ページにリダイレクト（502-511行目）

3. **オーナーページ** (`app/o/[ownerToken]/page.tsx`)
   - `running`状態で、逐次モードかつ`revealed`状態のサンプルがある場合、結果ページへのリンクを表示

### ✅ 一斉モードの実装

1. **プレゼンターページ**
   - `closed`状態になった場合、結果ページにリダイレクトされない（`revealed`状態のみリダイレクト）
   - `closed`状態の表示で、「ホームに戻る」ボタンを表示

2. **参加者のセッションページ**
   - `closed`状態のサンプルがある場合、結果ページにリダイレクトされない（`revealed`状態のみリダイレクト）

## テスト結果

### E2Eテストのエラー

- **エラー**: 参加登録を締め切るボタンが見つからない
- **原因**: 模擬参加者を作成した後に、UIが更新されるまで待つ必要がある
- **対策**: `waitForParticipantsToAppear`を使用するように修正済み

### テストの修正

- `waitForParticipantsToAppear`を使用して、参加者が登録されるまで待つように修正
- `localStorage`のキーを`bd:participant_token:${joinToken}`形式に統一
