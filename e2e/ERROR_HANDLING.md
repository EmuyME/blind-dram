# エラーレポートの対処方法

## エラーレポートの確認方法

### 1. HTMLレポートを開く（推奨）

```bash
npx playwright show-report
```

ブラウザが開き、以下の情報が表示されます：
- 失敗したテストの一覧
- エラーメッセージ
- スクリーンショット
- 実行ビデオ
- エラーコンテキスト

### 2. エラーファイルを直接確認

エラーレポートは以下の場所に保存されます：

```
test-results/[テスト名]-[ブラウザ]/error-context.md
test-results/[テスト名]-[ブラウザ]/test-failed-1.png
test-results/[テスト名]-[ブラウザ]/video.webm
```

## よくあるエラーと対処方法

### エラー1: ページが「読み込み中...」で止まる

**エラーメッセージ：**
```
Error: locator.waitFor: Timeout 10000ms exceeded
```

**原因：**
- 開発サーバーが起動していない
- ページが正しく読み込まれていない
- ネットワークエラー

**対処方法：**

1. **開発サーバーを起動**
   ```bash
   # 別のターミナルで実行
   npm run dev
   ```

2. **開発サーバーが正常に動作しているか確認**
   - ブラウザで `http://localhost:3000` にアクセス
   - ページが表示されることを確認

3. **テストを再実行**
   ```bash
   npm run test:e2e -- e2e/simple-test.spec.ts --project=chromium
   ```

### エラー2: セレクタが見つからない

**エラーメッセージ：**
```
Error: locator.waitFor: Timeout 10000ms exceeded
Call log:
  - waiting for locator('button:has-text("参加登録を締め切る")')
```

**原因：**
- UIが変更された
- ボタンが無効化されている
- ページが完全に読み込まれていない

**対処方法：**

1. **スクリーンショットを確認**
   ```
   test-results/[テスト名]-[ブラウザ]/test-failed-1.png
   ```
   実際の画面を確認して、期待する要素が存在するか確認

2. **ビデオを確認**
   ```
   test-results/[テスト名]-[ブラウザ]/video.webm
   ```
   テスト実行の過程を確認

3. **セレクタを修正**
   - 実際のUIに合わせてセレクタを更新
   - `e2e/helpers.ts` の該当箇所を修正

### エラー3: タイムアウトエラー

**エラーメッセージ：**
```
Test timeout of 60000ms exceeded
```

**原因：**
- 処理に時間がかかりすぎている
- ネットワークが遅い
- データベース接続が遅い

**対処方法：**

1. **タイムアウトを延長**
   ```bash
   npm run test:e2e -- --timeout=120000
   ```

2. **開発サーバーのパフォーマンスを確認**
   - コンソールにエラーがないか確認
   - データベース接続を確認

### エラー4: 開発サーバーに接続できない

**エラーメッセージ：**
```
Error: page.goto: net::ERR_CONNECTION_REFUSED
```

**原因：**
- 開発サーバーが起動していない
- ポートが使用されている

**対処方法：**

1. **開発サーバーを起動**
   ```bash
   npm run dev
   ```

2. **ポートが使用されている場合**
   ```bash
   # ポート3000を使用しているプロセスを確認
   netstat -ano | findstr :3000
   
   # プロセスを終了（必要に応じて）
   taskkill /PID [プロセスID] /F
   ```

## エラーレポートの活用方法

### 1. スクリーンショットで問題を特定

スクリーンショットを見て、以下を確認：
- ページが正しく表示されているか
- 期待する要素が存在するか
- エラーメッセージが表示されているか

### 2. ビデオで実行過程を確認

ビデオを見て、以下を確認：
- どのステップで失敗したか
- ページの読み込みに時間がかかっているか
- 予期しない動作が発生しているか

### 3. エラーコンテキストで詳細を確認

`error-context.md` には以下が含まれます：
- ページのスナップショット
- エラーメッセージ
- スタックトレース

## 自動修正機能の活用

一部のエラーは自動修正機能で対処できます：

```bash
npm run test:e2e:fix -- --project=chromium
```

このコマンドで：
1. エラーを自動検出
2. エラーパターンに応じて自動修正
3. 修正後の動作を検証

## エラーレポートの共有方法

問題が解決しない場合、以下の情報を共有してください：

1. **エラーメッセージ**
   - コンソールに表示されたエラーメッセージ

2. **スクリーンショット**
   - `test-results/[テスト名]-[ブラウザ]/test-failed-1.png`

3. **ビデオ**
   - `test-results/[テスト名]-[ブラウザ]/video.webm`

4. **エラーコンテキスト**
   - `test-results/[テスト名]-[ブラウザ]/error-context.md`

5. **開発サーバーのログ**
   - 開発サーバーのコンソール出力

## トラブルシューティングのチェックリスト

- [ ] 開発サーバーが起動しているか
- [ ] `http://localhost:3000` にアクセスできるか
- [ ] データベース接続が正常か
- [ ] ネットワーク接続が正常か
- [ ] タイムアウト設定が適切か
- [ ] セレクタが正しいか
- [ ] ページが完全に読み込まれているか

## 次のステップ

1. **エラーレポートを確認**
   ```bash
   npx playwright show-report
   ```

2. **スクリーンショットとビデオを確認**
   - 実際の画面を確認
   - テスト実行の過程を確認

3. **対処方法を実行**
   - 上記の対処方法を試す
   - 必要に応じてセレクタを修正

4. **テストを再実行**
   ```bash
   npm run test:e2e -- e2e/simple-test.spec.ts --project=chromium
   ```
