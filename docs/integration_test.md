# Blind Dram – 統合テスト手順書（MVP）

このドキュメントは、Blind Dram MVPの統合テスト手順を定義する。  
**飲み会1回分のフローが完走できることを確認する。**

---

## テスト環境

- **データベース:** Supabase（PostgreSQL）
- **フロントエンド:** Next.js（開発サーバー）
- **テストブラウザ:** Chrome / Safari（モバイル実機も推奨）

---

## テストシナリオ1: 参加登録→順番決め→開始

### 前提条件
- Supabaseデータベースがセットアップ済み
- 環境変数（`NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`）が設定済み

### 手順

#### 1. イベント作成（Owner）
1. `/create` にアクセス
2. イベント名を入力（例：「テストイベント2024」）
3. 回答モードを選択（「逐次モード」または「一斉モード」）
4. 「イベントを作成」ボタンをクリック
5. **確認:** Owner URL（`/o/[ownerToken]`）にリダイレクトされる
6. **確認:** 参加登録URL（`/s/[joinToken]`）が表示される

#### 2. 参加登録（参加者1）
1. 参加登録URL（`/s/[joinToken]`）にアクセス
2. 表示名を入力（例：「参加者A」）
3. 持参するボトル数を入力（例：2）
4. ボトルのラベルを入力（例：「Sample A」「Sample B」）
5. 「参加登録する」ボタンをクリック
6. **確認:** `participant_token`がlocalStorageに保存される
7. **確認:** 参加者ホーム（`/session/[joinToken]`）にリダイレクトされる

#### 3. 参加登録（参加者2）
1. 同じ参加登録URLにアクセス
2. 表示名を入力（例：「参加者B」）
3. 持参するボトル数を入力（例：1）
4. ボトルのラベルを入力（例：「Sample C」）
5. 「参加登録する」ボタンをクリック
6. **確認:** 参加登録が完了する

#### 4. 参加登録締切（Owner）
1. Owner URL（`/o/[ownerToken]`）にアクセス
2. **確認:** 参加者一覧が表示される（参加者A、参加者B）
3. 「参加登録を締め切る」ボタンをクリック
4. **確認:** Session状態が`ordering`に変更される
5. **確認:** Sample一覧が表示される（Sample A、Sample B、Sample C）

#### 5. 順番決め（Owner）
1. Owner URLでSample順番リストを確認
2. **確認:** 各Sampleに持ち込み主の名前が表示される
3. Sampleをドラッグ&ドロップで順番を変更
4. 「順番を保存」ボタンをクリック
5. **確認:** 順番が保存され、Toast通知が表示される

#### 6. Session開始（Owner）
1. 「Sessionを開始する」ボタンをクリック
2. **確認:** Session状態が`running`に変更される
3. **確認:** フレーバーチャートスナップショットが保存される

### 期待結果
- すべてのステップが正常に完了する
- エラーメッセージが表示されない
- 状態遷移が正しく行われる

## テストシナリオ2: Round進行（回答入力→Truth入力→採点→終了）

### 前提条件
- テストシナリオ1が完了している
- Session状態が`running`
- Sampleが3つ以上存在する

### 手順

#### 1. Round開始（Presenter）
1. Sample Aの持ち込み主（参加者A）がPresenterパネル（`/session/[joinToken]/presenter/[sampleId]`）にアクセス
2. **確認:** Round状態が`pending`であることを確認
3. 「Roundを開始する」ボタンをクリック
4. **確認:** Round状態が`answering`に変更される

#### 2. 回答入力（参加者A）
1. 参加者ホーム（`/session/[joinToken]`）にアクセス
2. **確認:** 「Sample A の回答を入力してください」が表示される
3. 「回答入力へ」ボタンをクリック
4. 回答入力画面で以下を入力：
   - カスク: 「シェリー樽」
   - 地域: 「スコットランド」
   - 熟成年数: 12
   - 度数: 43
   - 蒸留所名: 「マッカラン」
   - Nose: Tier1「フルーティ」「樽熟成」、Tier2「レモン, バニラ」
   - Palate: Tier1「フルーティ」、Tier2「オレンジ」
   - Finish: Tier1「樽熟成」、Tier2「キャラメル」
   - 点数: 85
5. 「下書き保存」ボタンをクリック
6. **確認:** 「下書きを保存しました」のToast通知が表示される
7. 「提出する」ボタンをクリック
8. **確認:** 「回答を提出しました」のToast通知が表示される
9. **確認:** 参加者ホームにリダイレクトされる

#### 3. 回答入力（参加者B）
1. 参加者Bが同じ手順で回答を入力・提出
2. **確認:** 回答が正常に保存される

#### 4. Truth入力（Presenter）
1. Presenterパネル（`/session/[joinToken]/presenter/[sampleId]`）にアクセス
2. **確認:** 参加者進捗が表示される（参加者A: 提出済、参加者B: 提出済）
3. 正解情報を入力：
   - カスク: 「シェリー樽」
   - 地域: 「スコットランド」
   - 熟成年数: 12
   - 度数: 43
   - 蒸留所名: 「マッカラン」
4. 「正解情報を保存」ボタンをクリック
5. **確認:** Round状態が`grading`に変更される

#### 5. 採点（Presenter）
1. Presenterパネルで参加者の推測を確認
2. 参加者Aの蒸留所名推測に対して「○」ボタンをクリック
3. 参加者Bの蒸留所名推測に対して「×」ボタンをクリック
4. **確認:** 採点が保存され、参加者進捗が更新される

#### 6. Round終了（Presenter）
1. 「Roundを終了する」ボタンをクリック
2. **確認:** Round状態が`revealed`（逐次モード）または`closed`（一斉モード）に変更される
3. **確認:** 参加者ホームにリダイレクトされる

### 期待結果
- すべてのステップが正常に完了する
- 回答が正しく保存される
- 採点が正しく記録される
- 状態遷移が正しく行われる

## テストシナリオ3: 集計・公開→結果表示

### 前提条件
- テストシナリオ2が完了している
- すべてのRoundが終了している

### 手順

#### 1. 集計実行（Owner）
1. Owner URL（`/o/[ownerToken]`）にアクセス
2. **確認:** Session状態が`aggregating`であることを確認
3. 「集計を実行する」ボタンをクリック（または自動実行）
4. **確認:** 集計が完了する

#### 2. 結果公開（Owner）
1. 「結果を公開する」ボタンをクリック
2. **確認:** Session状態が`published`に変更される

#### 3. 結果表示（参加者）
1. 参加者ホーム（`/session/[joinToken]`）にアクセス
2. **確認:** 「結果が公開されました」が表示される
3. 「結果を見る」ボタンをクリック
4. **確認:** 結果ページ（`/session/[joinToken]/results`）が表示される
5. **確認:** 順位表が表示される
6. **確認:** 詳細タブで各Sampleの正解と参加者の回答が表示される

#### 4. CSV出力（Owner）
1. 結果ページで「CSVをダウンロード」ボタンをクリック
2. **確認:** CSVファイルがダウンロードされる
3. **確認:** CSVファイルがUTF-8 BOM付きで正しくエンコードされている
4. **確認:** 全データが含まれている

### 期待結果
- 集計が正しく実行される
- 順位が正しく計算される
- 結果が正しく表示される
- CSVが正しく出力される

## テストシナリオ4: モバイル実機テスト

### 前提条件
- テストシナリオ1〜3が完了している
- スマートフォン（iOS/Android）を用意

### 手順

#### 1. 画面表示確認
1. 各画面をスマートフォンで表示
2. **確認:** レイアウトが崩れていない
3. **確認:** テキストが読みやすい
4. **確認:** ボタンがタップしやすい（44x44px以上）

#### 2. 操作確認
1. 参加登録画面で入力・送信
2. **確認:** キーボード表示時にレイアウトが崩れない
3. **確認:** スクロールがスムーズ
4. **確認:** ドラッグ&ドロップが動作する（順番決め画面）

#### 3. パフォーマンス確認
1. 各画面の読み込み速度を確認
2. **確認:** 3秒以内に表示される
3. **確認:** API呼び出しが正常に完了する

### 期待結果
- すべての画面がモバイルで快適に使える
- 操作がスムーズ
- パフォーマンスが許容範囲内

## バグ修正チェックリスト

### よくあるバグパターン

1. **認証エラー**
   - [ ] `participant_token`が正しく保存・取得されるか
   - [ ] `owner_token`が正しく検証されるか
   - [ ] トークンが無効な場合のエラーハンドリング

2. **状態遷移エラー**
   - [ ] Session状態が正しく遷移するか
   - [ ] Round状態が正しく遷移するか
   - [ ] 不正な状態遷移がブロックされるか

3. **データ整合性**
   - [ ] UNIQUE制約が正しく機能するか
   - [ ] 外部キー制約が正しく機能するか
   - [ ] データが正しく保存・取得されるか

4. **UI/UX**
   - [ ] エラーメッセージが適切に表示されるか
   - [ ] ローディング状態が適切に表示されるか
   - [ ] ボタンのdisabled状態が正しいか

5. **パフォーマンス**
   - [ ] API呼び出しが適切に最適化されているか
   - [ ] データベースクエリが効率的か
   - [ ] 不要な再レンダリングがないか
